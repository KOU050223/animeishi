# 12. 視聴実績バッジ（issue #415）

Issue: https://github.com/KOU050223/animeishi/issues/415

## 目的

視聴実績に応じたバッジを獲得できるようにし、記録を続ける動機づけと
名刺に載せる「見せたい中身」を増やす。最初のバッジは issue の決定どおり
3 種類。

| バッジ | 判定入力 | 閾値 |
| --- | --- | --- |
| 視聴数（段階制） | `watch_history.state = 'WATCHED'` の累計件数 | 10 / 50 / 100 / 300 / 500 / 1000 作品 |
| 連続記録（週単位・段階制） | `episode_records.recorded_at` | 4 / 12 / 26 / 52 週 |
| 今期完走 | `episode_records` × Annict episodes マスタ | 今期の作品を 1 本でも全話記録 |

## 判定はサーバーで都度計算し、獲得履歴テーブルは持たない

`GET /me/achievements` が認証ユーザーの実績一覧をその場で計算して返す
（`apps/api/src/features/achievements/`）。獲得日時を永続化するテーブルは
意図的に作っていない。

- 採らなかった案: `achievements` / `user_achievements` テーブルを作り、
  記録書き込み時に判定して獲得行を積む方式。
  - 判定ロジックの修正・バッジ追加のたびに既存ユーザーの獲得行との
    整合を考える必要が出る（バックフィル・獲得の取り消し）。
  - 「新規獲得の検出」はクライアント側の既見キー（AsyncStorage）との
    差分で十分実現できる（後述）。
- 前提が変わったとき: 獲得日時の表示・獲得の取り消し不可証明・
  プッシュ通知トリガなど「サーバー側で獲得イベントが要る」要件が出たら
  テーブルを追加する。`recorded_at` を持つ `episode_records` があるため、
  バックフィルで近似的な獲得日時は再構成できる。

## 週単位の連続記録

- 「1 話以上記録した JST の週（月曜始まり）」が連続した最長週数で判定する。
  anime の放送が週単位サイクルなので週区切りとし、境界はアプリの対象
  ユーザーに合わせて JST 固定にした（`jstWeekIndex`。サーバーの
  タイムゾーンに依存しない）。
- 獲得判定には**最長週数**を使う。一度 4 週達したユーザーがストリークを
  切っても獲得済みバッジを失わない。「途中で取り消される」体験は
  モチベーションを下げるため。
- 進捗表示には**現在の連続週数**を使う。今週まだ記録が無くても
  先週までが連続していれば「継続中」とみなす（月曜 0 時を過ぎただけで
  ストリークが 0 に見えないようにするため）。

## 今期完走

- 「今期」は Annict のシーズン（`currentAnnictSeason()`、JST 基準の
  `<year>-<season>`）と `annict_works.season_name` の一致で判定する。
- 「完走」は `episode_records` に記録がある話が、Annict episodes マスタの
  全話を覆うこと。話数マスタは Annict が正（issue #415 決定）。
- Annict からの話数取得は `searchWorks(annictIds:)` の一括クエリ
  （`fetchAnnictWorksEpisodeIds`、1 作品 100 話まで）で行う。作品ごとの
  episodes 取得だと今期 30 作品で 30+ サブリクエストになり Workers の
  上限を超えるため。100 話超の長期作品だけ `fetchAnnictWorkEpisodes`
  のページング取得にフォールバックする（季節ものでは稀なケース）。
- 判定候補は「今期の作品で 1 話でも記録があるもの」に限定する。今期
  全作品の話数を毎回引くのはコストが大きく、「今期の記録をまだ
  付けていない」ユーザーは未獲得で確定するため。
- 未連携（Annict トークン無し）や Annict 障害で話数マスタを取れない
  ときは、その実績だけ `available=false` で返す。実績一覧全体を
  落とさないことが目的（他の実績は Annict に依存しない）。
- 進捗は「最も完走に近い作品」の `記録済み話数/全話数` を返す。
  0 話作品・マスタ未取得の作品は対象外（0 除算と誤判定を防ぐ）。

## 「新しく獲得した」検出とお祝い表示

- サーバーが獲得履歴を持たないため、端末（AsyncStorage、ユーザーごと）
  に「確認済みの獲得キー」を保存し、API 応答との差分を新規獲得とする。
- 獲得キーは実績 ID。今期完走だけは `season_completion@<season>` の
  形式でシーズンを含め、次のシーズンでも再度お祝いが出るようにする。
- 既見キーが一度も保存されていない初回は差分を取らずベースライン
  として保存だけする（機能追加前からの獲得分が初回起動でまとめて
  お祝い表示されるのを防ぐ）。
- 話の記録・視聴ステータス更新のミューテーションが settle したら
  実績クエリを無効化し、次回取得で差分があればお祝いを出す。

## 名刺要素としての実績バッジ

- 既存の `animeCountBadge`（視聴数バッジ）と同じ構造の新要素
  `achievementBadge` を追加した。`kind` で表示する実績カテゴリを選び、
  獲得済みの最高段の名前（例「視聴 100 作品」）を表示する。
- 未獲得の場合は最初の段の名前に「（未獲得）」を付けて表示する。
  空欄にすると要素の存在自体が分からず、編集・共有で困惑するため。
- 描画データは `MeishiRenderContext.achievements` に載せ、
  `useMeishiRenderContext` と名刺エディタの両方で `useAchievements`
  の値を流す。共有画像スナップショットは同じコンテキストを使うため
  追加の配線は不要。

## API レスポンス

`GET /me/achievements` は `{ achievements, season, stats }` を返す。
`season` は獲得キーに含めるシーズン判定値、`stats` は進捗表示の補助
（視聴数・現在/最長ストリーク）。各実績は `{ id, kind, threshold, earned,
available, progress: { current, target }, work? }`。

`available` は「判定に必要なデータが揃わなかった」ことを表す。
現状は今期完走の Annict 話数マスタ取得失敗のみが false になり得る。
